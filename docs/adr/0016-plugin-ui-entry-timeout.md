# 0016. 插件界面异步入口等待上限与作用域撤销

- 状态：accepted
- 记录日期：2026-10-26
- 关联：ADR-0014（补充等待、超时与过期回收语义）

## 技术背景

`packages/web/src/lib/pluginUi.ts` 的 `doSync` 顺序加载插件，`syncPluginUi` 复用在途任务。
ADR-0014 开始等待显式入口结算后，永不结束的 `register(host)` 会阻塞本轮后续加载与所有同步。
真实浏览器夹具将挂起入口置于最前后，正常插件在 20 秒内没有加载，失败清单也为空。

仅使用 `Promise.race` 不够：原 Promise 不会取消，迟到回调仍可能注册组件，
或按同一 owner 批量注销已经重新启用的新一代贡献。

## 考虑选项

1. 保留无限等待，要求插件作者保证结束。
2. 超时后只结束等待，不撤销已交付宿主的注册能力。
3. 对显式入口设置固定等待上限，并让注册宿主和资源回收与加载代次绑定。

## 决策结果

选择选项 3。显式 `register(host)` / 默认导出的入口结算上限为 15 秒，
采用加载器内部常量，不增加清单字段或运行环境变量。
超时归入现有版本失败去重路径，回收已登记贡献，管理台和插槽提示显示超时原因，
随后继续加载其他入口；停用后清除，重新启用或版本变化后可重试。

宿主注册与批量注销入口在该代次撤销后不再修改注册表。
停用、加载失败、超时或迟到结算都撤销作用域，停用同时结束正在等待的显式入口；
晚到的清理函数仍执行一次，其使用旧宿主的注册/注销调用不再影响新代次。
注销 token 保持幂等；对原 Promise 的成功与拒绝继续消费，避免迟到拒绝成为未处理异常。

模块求值期间和显式入口的同步调用期间仍安装插件作用域全局 SDK；
开始等待入口返回值时恢复全局 SDK。异步代码必须保留入口参数或已经取得的作用域引用，
不能依赖稍后重新读取全局对象来获得该插件的归属。

## 后果

### 正面

- 挂起的显式入口在有限时间后可见失败，后续插件和同步恢复。
- 超时或停用后的旧宿主不能追加贡献，也不能清掉同名插件的新一代注册。
- 不改变 Manifest、宿主 SDK 的形状或服务端插件启用状态。

### 负面 / 风险（如实）

- 合法但初始化超过 15 秒的插件也会超时；耗时工作应在组件生命周期或工具调用中完成。
- Promise 及插件创建的计时器、网络请求不会被强制取消；插件应在自己的清理函数中管理它们。
- 上限只覆盖显式入口结算；模块下载、ESM 顶层 await 仍受模块加载机制约束，不在本次强制终止范围。
- JavaScript 同步死循环会阻塞主线程，计时器无法抢占；同源插件也能重新取得全局 SDK 或直接操作 DOM。
  这是一项可用性保护，不构成插件沙箱。
- 模块仍按 URL 缓存；更新模块产物后可能需要刷新页面，见 ADR-0014。
