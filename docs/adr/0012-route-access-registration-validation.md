# 0012. 路由声明在注册期校验，旧 JavaScript 调用保留迁移窗口

- 状态：accepted
- 记录日期：2026-10-26
- 关联：ADR-0006、ADR-0010

## 技术背景

启动末尾的访问等级审计能发现已经进入路由表的隐式公开路由，但插件热启用后不会重新审计。
`opts` 和 `access` 的类型又均为可选，TypeScript 作者遗漏声明也能通过检查。
此外 JavaScript 可传入 `null` 等非法访问等级，不能只依赖静态类型。

## 考虑选项

1. 保持仅启动末尾审计。
2. 默认将所有省略声明的调用改为登录后可用。
3. 收紧 TypeScript 契约，在注册前校验严格模式与非法值，并保留旧 JavaScript 的非严格迁移窗口。

## 决策结果

选择第三项。

- `HttpRouterService.register` 的第 4 参及 `RouteAccessOptions.access` 必填；
  调用方需选择 `public`、`user` 或 `admin`。`owner` 继续仅用于可观测性。
- 内置路由器在创建时读取 `GEEWIKI_STRICT_ROUTE_ACCESS`，仅字面量 `1` 开启严格模式。
  严格模式下未声明访问等级的调用在加入路由表前抛错，启动与热启用都适用。
- 所有模式均拒绝非法访问等级，包括 `null`、拼写错误与非字符串值。
- 路由器保留首次注册校验失败，启动末尾审计会重新抛出；避免插件管理器记录加载失败后，
  宿主因路由表为空而把严格启动误判为成功。启动失败沿用现有资源清理。
- 非严格模式继续接受旧 JavaScript 省略声明的调用，默认公开并保留启动聚合告警。
  不在本次变更中把旧公开接口自动改成登录接口；迁移方式是补齐显式声明后开启严格模式。
- 审计第三方路由器时仍使用可选 `routes()`。本决策不改变 Manifest 或前端宿主 API。

## 后果

### 正面

- TypeScript 作者能在调用点发现遗漏；严格部署的后加载插件也不能注册隐式公开路由。
- 非法值无法通过空值默认逻辑变成公开路由；失败调用不留下对应路由。
- 保留第三方 JavaScript 插件的兼容窗口，公开接口的权限由作者明确选择。

### 负面 / 风险（如实）

- 消费 core 类型的外部 TypeScript 插件需要补齐第 4 参及 `access`。
- 非严格模式的旧 JavaScript 仍有默认公开边界，完整默认收紧需后续迁移决策。
- 注册校验不提供沙箱，也不替插件清理此前已注册的其他资源；插件仍需自行管理生命周期。
