# 0014. 插件界面入口结算与失败诊断

- 状态：accepted
- 记录日期：2026-10-26

## 技术背景

`packages/web/src/lib/pluginUi.ts` 的 `loadPluginUi` 已把模块导入失败记录为可见状态，
但显式 `register(host)` 的同步异常只写控制台，异步返回值没有被等待。
结果是同一坏版本可反复执行，异步拒绝绕过回滚，插件也可能在入口完成前被标为已加载。
加载期间的停用已经用代次识别；等待入口后同样需要复核。

## 考虑选项

1. 只把同步异常加入失败清单，保留 Promise 被忽略的行为。
2. 把 Promise 入口视为错误，要求所有插件同步注册。
3. 等待显式入口结算，统一导入与执行失败的诊断、回滚和版本去重。

## 决策结果

选择选项 3。显式 `register(host)` 或默认导出的入口可同步返回，也可返回 Promise；
结算结果中的清理函数与贡献一起回收。入口没有结算前，不标记成功或注入该插件 CSS。

导入或执行失败后先回收部分注册，再记录当前版本失败、通知状态订阅者。
失败版本不自动重复执行；新版本会重试，停用后提示消失，成功后清除失败状态。
入口等待期间若插件已卸载、被替换或不再需要，其迟到结果仅回收，不写入成功或失败状态。
顶层注册形态继续使用同一作用域宿主并接受相同回滚；不改变插件清单或服务端启停状态。

## 后果

### 正面

- 同步和异步执行异常都进入现有界面提示、管理台和失败版本去重路径。
- 错误版本不会每轮轮询重复执行；迟到成功不会复活已经卸载的界面。
- 显式入口返回的异步清理函数得到正确回收。

### 负面 / 风险（如实）

- 等待一个永不结算的 Promise 会阻塞当前加载队列；本决策不引入超时或强制终止机制。
- 只能回收经过宿主登记的贡献及插件提供的清理函数，无法撤销插件私自创建的计时器或网络请求。
- ESM 模块仍按 URL 缓存；版本变化不等于浏览器重新求值模块，更新产物后可能需要刷新页面。
- 服务端插件处于启用状态与浏览器界面成功是两种状态；界面失败不会自动停用服务端插件。
