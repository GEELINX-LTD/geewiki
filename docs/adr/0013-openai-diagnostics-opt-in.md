# 0013. 上游错误诊断日志仅显式开启

- 状态：accepted
- 记录日期：2026-10-26

## 技术背景

`packages/plugin-openai/src/provider.ts` 的 `configLogEnabled()` 原先仅在
`GEEWIKI_OPENAI_DEBUG=0` 时关闭日志。未配置与其他字符串都会在上游 HTTP 错误时
输出错误体摘要。`redact()` 是启发式，不能保证任意上游文本中的敏感信息都被识别。
默认开启使未选择诊断输出的部署也增加一个日志出口。

## 考虑选项

1. 保持默认开启，仅补充文档：排障方便，但默认日志出口不变。
2. 默认关闭，接受多种真值（如 `true` / `yes`）：增加配置歧义，也与现有严格开关取值不一致。
3. 默认关闭，仅精确字符串 `1` 开启：行为明确，部署者主动选择增加诊断内容。

## 决策结果

选择选项 3：只在 `process.env['GEEWIKI_OPENAI_DEBUG'] === '1'` 时输出这条诊断日志。
未设置、空串、`0`、`false`、`off` 及其他值均关闭。开关仍逐请求读取。

保留上游错误码归一化、无重试和错误 chunk 不携带上游消息的既有行为。
显式开启后仍只记录上游错误体前 500 字符经 `redact()` 处理后的摘要，
不另行记录请求体。该机制不阻止上游把请求上下文回显到错误体，也不提供日志访问控制。

部署变量的默认值、取值与使用方式以 [deployment.md](../deployment.md) 为真源。
回归使用本机 HTTP 夹具验证各开关值下日志数量、归一化错误及显式开启时的密钥脱敏。

## 后果

### 正面

- 默认部署不再将上游错误体写入这条诊断日志。
- 配置取值可预测，错误码与客户端响应行为保持一致。

### 负面 / 风险（如实）

- 依赖默认诊断日志排障的部署需显式设置 `GEEWIKI_OPENAI_DEBUG=1`。
- `redact()` 仍是启发式；显式开启后，未识别的敏感内容仍可能进入日志。
- 开关只控制适配器的这一条上游错误诊断，不控制其他插件或宿主的日志。
