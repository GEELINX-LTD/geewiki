# 0015. 插件界面声明与运行期注册的一致性诊断

- 状态：accepted
- 记录日期：2026-10-26

## 技术背景

服务端入口表包含已经仲裁生效的插槽、扩展节点和页面路由；浏览器才掌握组件是否真正注册。
`loadPluginUi` 成功只表示模块和显式入口执行完毕，不能证明它承诺的界面都已就绪。
按需加载和异步入口又使得「声明存在、当前没有组件」并不总是错误。

## 考虑选项

1. 服务端解析产物或维护浏览器上报表，再把差集加入 `skipped`。
2. 声明有缺项时视为整个入口失败，回滚全部贡献并自动重试。
3. 浏览器在入口结算后核对实际注册表，管理台显示可自愈的未就绪提示。

## 决策结果

选择选项 3。以当前入口表中生效的 `slots`、`extNodes`、`routes` 为预期，
以插槽/扩展点和路由的现有注册表及真实 owner 为事实；不维护另一份注册账本。
只检查已成功加载且版本仍对应的插件。未加载的按需入口、等待中的异步入口、
被服务端抑制的节点，以及没有相应声明的兼容注册不作为缺项。

界面状态快照增加声明缺项，管理台列出插件及缺少的位置；不改变服务端启用状态、
不归入导入/执行失败、不卸载已正常工作的贡献，也不触发自动重试。
入口结算后继续订阅真实注册表：延迟注册会清除提示，主动注销会重新显示未就绪，
插件卸载会结束诊断。停止同步时释放订阅。

不改 Manifest、服务端入口表或宿主 SDK 的 schema。判断规则由浏览器实现，
作者入口时机以 `docs/plugin/api-reference.md` 为准，诊断展示以 `docs/plugin-platform.md` 为准。

## 后果

### 正面

- 可以区分「入口失败」和「入口已执行，但声明的界面未就绪」，并准确指出 owner 和缺项。
- 插槽与扩展点复用同一真实注册表，路由检查归属，避免把被拒绝的调用算成成功。
- 延迟注册、注销和插件卸载都可更新诊断，不依赖下次十五秒轮询。

### 负面 / 风险（如实）

- 只判断是否登记了组件，不能保证组件实际渲染成功或视觉正确；渲染错误仍由现有错误边界处理。
- 入口返回后才通过计时器、事件等注册的插件，在完成注册前会显示「尚未就绪」；
  若首次加载依赖异步工作，应返回对应 Promise。
- 只核对入口表中已经下发的生效声明；无法诊断旧服务端未下发的声明，也不逐个核对扩展模式。
