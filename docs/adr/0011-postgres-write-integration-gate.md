# 0011. PostgreSQL 并发写入进入测试门禁

- 状态：accepted
- 记录日期：2026-10-26
- 关联：ADR-0003、ADR-0009、ADR-0010

## 技术背景

保存前置条件依赖数据库事务、行锁和唯一约束。现有异步服务测试使用 SQLite 的异步门面，
适配器单测则注入连接池替身，二者都不能验证真实 PostgreSQL 的锁等待与回滚。
手动 PostgreSQL shell 验收仍未进入主门禁，数据库特有的写入回归容易漏检。

## 考虑选项

1. 保留手工验收，只扩充 SQLite 与连接池替身测试。
2. 在现有 `test` 作业中增加真实 PostgreSQL 写入验收，使用两个独立宿主和连接池竞争同一个临时数据库。
3. 新增数据库版本矩阵、完整部署验收与独立 required check。

## 决策结果

选择第二项，使用 PostgreSQL 17 服务容器，不改 required check 名称或发布依赖关系。

- 新增独立命令 `pnpm test:postgres`，普通 `pnpm test` 保持无需外部数据库。
  CI 的 `test` 作业必须执行两条命令；连接失败、迁移失败或未能形成竞争都直接失败，不跳过。
- 连接参数使用标准 `PGHOST` / `PGPORT` / `PGDATABASE` / `PGUSER` / `PGPASSWORD`。
  `PGDATABASE` 必须显式指定。该库仅作为控制连接，验收创建随机命名的新库并在结束后删除，
  因此测试账号需要建库权限；不对指定库的业务表做清理或写入。
- 通过数据库锁等待确认两个独立写事务都已进入竞争，再释放阻塞；断言最终页面、历史、块与出链状态。
  验收覆盖同基线更新、同名创建、删除重建、只读主体拒写与写入中途失败回滚。
- 使用真实内置注册表、PostgreSQL 迁移和策略服务，不替换生产 SQL 或权限判定。

## 后果

### 正面

- PostgreSQL 方言下的保存冲突和事务回滚成为发布前必经检查。
- 竞争由数据库状态确认，不依赖碰巧交错的请求时序。
- 本地常规测试继续保持轻量，专用验收可重复运行并自动回收测试数据库。

### 负面 / 风险（如实）

- `test` 作业增加容器启动与集成验收时间，也依赖 PostgreSQL 镜像可用。
- 本地运行需要可连接的 PostgreSQL 与有建库权限的测试账号；强制终止进程时可能遗留随机测试库。
- 只覆盖 PostgreSQL 17 的页面写入链路，不代表其他数据库版本、全部手动 e2e 或完整部署均已验证。
- 两个宿主仅用于制造数据库竞争；不改变 ADR-0009 的单进程部署边界，也不宣称附件与身份流程支持多实例。
