# 0018. 离线恢复的完整预检、暂存与双目录回退

- 状态：accepted
- 记录日期：2026-10-26

## 技术背景

`packages/manager/src/backup.ts` 的 `restoreBackup` 在哈希验证后先移开数据目录，
随后边校验路径边写入目标。后置非法路径会在数据库和配置已被替换后才报错；
配置也没有与数据对应的留底。`verifyBackup` 只校验内容哈希，不足以证明可安全恢复。

## 考虑选项

1. 只把路径检查提前，继续向目标逐文件写入。
2. 引入带持久日志、启动恢复和 fsync 协议的跨目录事务。
3. 完整预检，在每个目标的同级暂存，再换入目录；可捕获的提交失败回退两边。

## 决策结果

选择选项 3，维持离线恢复及备份格式 v1，不增加依赖。

- 任何写入之前校验清单结构、规范逻辑路径、重复与文件/目录冲突、大小、哈希以及源文件类型。
  清单只接受 `data/…` 与 `config/*.json`，拒绝穿越、符号链接、非普通文件和 SQLite 陈旧边车。
- 数据与配置目标不能重叠，不能覆盖仓库根或包含备份源；校验目标目录树与文件类型。
  任何会被覆盖的文件、以及完整数据库恢复会替换的非空数据目录，均要求 `--force`。
- 先在两个目标各自的同级临时目录准备内容，再校验暂存文件。含数据库的备份重建整个数据目录；
  不含数据库的部分备份及配置目录保留未列入清单的原文件，再覆盖清单条目。
- 提交时把原数据、原配置分别移到同级 `.pre-restore-…`，再换入暂存目录。
  正常成功保留两份原状；可捕获失败按相反顺序撤回已换入目录、移回原目录。
  回退失败时保留原目录并明确报告位置，不声称已恢复原状。
- `--verify-only` 验证备份自身；新增 `--dry-run` 验证与实际恢复相同的目标和覆盖条件，不写文件。
  库的 `validateRestore` 与实际恢复使用同一预检，避免 CLI 产生两套判断。

## 后果

### 正面

- 后置非法条目、符号链接和目标冲突在任何目标被改动之前拒绝。
- 复制失败发生在暂存阶段；提交异常有原数据和配置可共同回退。
- 原配置和密钥同样留底，恢复后可用实际部署目录启动服务验收。

### 负面 / 风险（如实）

- 暂存和留底需要额外空间，配置覆盖保留未在包中的文件；恢复仍要求停服和排除并发文件修改。
- 两个目录的 rename 不是跨目录、跨卷原子事务；进程强杀、断电、文件系统故障或回退本身失败，
  仍可能需要根据留底目录手工恢复。本决策不提供持久恢复日志或崩溃自动恢复。
- 不支持链接或特殊文件的恢复。信任显式配置的根目录及其现有父目录；不隔离有权限并发改文件的本机用户。
- 校验和检测损坏，不证明备份来源可信；未检查数据库逻辑完整性或所有插件配置语义，
  不含数据库的备份也不会补齐数据库。PostgreSQL 仍需单独的 pg_dump/pg_restore。
- 密钥可能同时存在于备份、暂存和留底中，文件及目录权限必须按敏感产物管理。
