# 特殊结构

这一页演示 GeeWiki 在"一篇 Markdown"之外提供的结构。**本页自身就是第一个例子。**

## 层级 slug

本页 slug 是 `guide/special-structures`——`/` 分层的子页，父级 `guide` 的权限收紧会
**自动继承**到本页（子页的「权限」面板里能看到继承自谁）。规则：

- 每段以小写字母或数字开头，可含 `a-z 0-9 . _ -`；总长 ≤ 80，层级有深度上限；
- 首段不能是 `search` / `ask` / `new` / `list`（它们是功能路由），
  第二段不能是 `edit`（`<slug>/edit` 是编辑路由）；
- `home` 是**约定的首页**：打开 wiki 默认显示 `home`（它是普通页面，不是保留字）。

## Wikilink 与反链

- `[[guide/features]]` → 自动渲染成目标页标题：[[guide/features]]
- `[[guide/features|自定义显示文本]]` → [[guide/features|自定义显示文本]]
- 指向不存在的页面 → 红链：[[example/尚未创建的页面]]（点击即可创建——红链是入口不是错误）
- 每个目标页底部的**反链面板**会列出"谁链接了我"；围栏代码里的链接**不算**引用。

## 受限块（gated）

正文中用注释标记圈出的段落，按块计算可见性。下面这个块是 **org 档**——
组织成员看得见，匿名访客的页面里它整段消失：

<!--gated:org-->
> 受限块内容演示：组织成员可见的段落。
> 如果你在**未登录**状态下能看到这段字，说明权限坏了，请立刻检查
> `policy-service` 的判定。
<!--/gated-->

规则：标记必须独占一行、成对出现、不能嵌套；未识别的档位名会**报错**（拒绝猜测）。
把标记**写进围栏代码**即可按字面演示（这也是本行源码这样显示的原因）：

```markdown
<!--gated:org-->
这一整段只对组织成员出现
<!--/gated-->
```

块还可以精确授予个人（`granted` 档）：在页面「权限」里对某一**块**授权指定成员。

## 版本历史

每次保存前，旧正文（连同**当时的块权限**）自动快照。页面下方「历史版本」可展开对比；
「恢复此版本」要求页面管理权，且会明确警告——恢复是一次真实的写操作，不是预览。

## 附件

阅读页的附件面板支持上传与浏览。列表需要该页**编辑权**；删除允许"编辑权或上传者本人"——
删自己传错的文件不该先看别人脸色。

## 访问申请

对完全够不着的页面（404 外观、摘要可见但正文不够），可申请访问并留言；
批准后你会出现在该页的显式授予里。

## 搜索行为

- 中文按 **trigram** 切分匹配，也支持带引号的整短语；
- 命中层与正文层各做一次权限过滤：搜不到"不该你看到的词"，命中片段里也不会带出
  受限块的字。

## 关于这批内置文档

你正读的这一整套（`home` 与 `guide/*`）由 `@geewiki/builtin-docs` 插件内置：

- **只读**：任何主体（含 owner）都无法编辑或删除它们——界面上不出现编辑入口，
  服务端判定同样拒绝，不是前端隐藏；
- **随项目更新**：内容版本号变化时，服务器启动过程自动同步为最新正文；
- **可隐藏**：管理员在「插件管理 → 内置文档」把 `hidden` 设为 `true`，
  整套文档对所有人（含管理员）即时视同不存在；关掉即恢复，页面本体从未被删除。

想写一份"属于你们团队自己的首页"？不必改动这些页面——把常用入口写进一个
新页面（比如 `team`），让大家从它出发即可。
